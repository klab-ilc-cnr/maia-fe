# Maia-fe — Agent Guide (AGENTS.md)

Reference doc for AI agents working on this repository. Keep it updated when the project changes.

## Overview

- **What it is**: MAIA is an open, collaborative web tool for text annotation, e-lexicography and lexical linking, built by [KLAB @ ILC-CNR](https://www.ilc.cnr.it/klab/). This repo is the **Angular frontend**: **Angular 14.2.9 on `master`**, **Angular 21.2 + PrimeNG 21.1 on `upgrade/angular-21`** (upgrade done up to the Angular 21 checkpoint; QA/merge pending) (project name in `angular.json`: `projectxFE`).
- **Backend**: `maia-be` (Spring Boot). Others: **TexO** (text backend; replaced the legacy CASH app) and **LexO** (lexicon backend).
- **Versions**: package.json `name: maia-fe`; `0.20.0` on `master` (last release, tagged `v0.20.0`), **`0.26.5` on `upgrade/angular-21`**. Docs/versions map in `README.md`. Upgrade convention: **Y +1 at each delivered Angular step, Z +1 at each delivered fix package**, X stays 0; set with `npm version X.Y.Z --no-git-tag-version`; **no git tags** for test versions. The footer shows the version and the e2e smoke checks it. Test packages are named `dist/maia-fe-<version>-test-<desc>-<timestamp>.zip` (superseded ones in `dist/old/`).
- **Branches**: `master` (stable; `study/security-fixes` fast-forwarded into it on 2026-11-04), `develop`. **Active work: `upgrade/angular-21`** (plan: `documentation/upgrade/angular-upgrade-plan.md`). `epic/#9044-…` is stale and fully contained in master. No CI workflows configured.

## Toolchain (MUST FOLLOW)

- **Node by branch (via nvm)**: `master` (Angular 14) → **Node 16.20.2** (newer Node breaks Angular 14). `upgrade/angular-21` (Angular 21) → **Node 22.23.4** (valid for Angular 18–22). Use: `export NVM_DIR="$HOME/.nvm"; source "$NVM_DIR/nvm.sh"; nvm use <version>`; `nvm` is a shell function (cannot be wrapped by `timeout`).
- TypeScript **4.8.4** on master / **5.9** on `upgrade/angular-21`.
- Commands:
  - `npm install` — fine on Node 16 (engine warnings are advisory).
  - `npm run build-prod` (=`ng build --configuration production --base-href='./'`) — **passes** (±30s). Budget warning only (initial 5.65 MB > 5 MB). *(master)*
  - **On `upgrade/angular-21`** (builder `@angular/build:application`, esbuild): `npx ng build -c production --base-href=""` → flat output in `dist/projectx-fe` (`outputPath.browser: ""`). **Do not pass `--output-path`** on the CLI (it replaces the outputPath object and re-adds `browser/`). Deploy packages are built this way and copied into `maia/`.
  - `npm start` (=`ng serve`) — dev server on `http://localhost:4200`, uses `src/proxy.conf.json`.
  - `npm test` (=`ng test`, karma/ChromeHeadless) — **BROKEN on master**: ~19 TS errors under `strict` (spec + app files), `Executed 0 of 0`. Pre-existing, not caused by security work. Fixing it is a separate task (172 `.spec.ts` exist).
  - `npm run compodoc` — offline doc generation (uses `tsconfig.doc.json`; compodoc 2 on the upgrade branch).
  - `npm run check-primeng-attrs` — lists static attributes on `<p-*>` that are not PrimeNG inputs and unknown `pTemplate` names. **Run it after every PrimeNG upgrade**: removed/renamed inputs written as static attributes (`field="x"`) compile fine and are silently ignored (bindings `[field]` do fail).
  - `npm run check-licenses` — fails if a PrimeUI-licensed package (PrimeNG 22, primeicons 8, `@primeuix/themes` 3…) or a PrimeTek `-lts` version enters `node_modules`. Run it after every dependency change.
- **Smoke e2e** (`e2e/`, see `e2e/README.md`): separate toolchain, **Node ≥ 20 via `nvm use 24.14.0`** (never the app's Node). Run against `ng serve`: `E2E_LABEL=<tag> E2E_EXPECT_TITLE="MAIA - VocaBO - DEV UPGRADE" npx playwright test`. Credentials in `~/.config/maia/e2e.env` (outside repo, 600; user `agente`, ADMINISTRATOR on the test VM). Uses/reuses workspace `e2e-smoke` (id 19). Run it after every upgrade step and compare `artifacts/screens/<tag>/` with the previous baseline. `tests/visual-tour.spec.ts` photographs pages, dialogs, open selects, menus and all tabs (read-only) for before/after theme comparisons.

## Project map (`src/`)

- `src/app/pages/` — routed views: `login`, `workspace`, `lexicon`, `tagsets`, `layers`, `usersManagement`.
- `src/app/controllers/` — components: `editors/` (form/sense/lexical editors, `p-editor` rich text), `explorers/` (ontology), `page-controllers/` (header/footer/loader), `popup/`, `tab-controllers/`, `tooltips/`, `viewers/`, `icons/`.
- `src/app/services/` — API services: `workspace` (texts/corpus via TexO), `authentication`, `dictionary`, `ontology`, `lexicon`, `storage`, etc. Interceptors in `src/app/interceptors/` (JWT via `authentication.interceptor`).
- `src/app/models/` — domain models (annotation, corpus, dictionary, lexicon, ontology, tagset, text, texto, tile…).
- `src/app/modules/shared.module.ts` — central NgModule exporting primeng modules (incl. `EditorModule`).
- `src/app/guards/` — `authGuard` (checks `StorageService.isLoggedIn()/isExpired()`).
- Other: `forms/` (autocomplete widgets), `layouts/`, `routes/`, `pipes/`, `helpers/`, `validators/`, `constants/`.
- `src/environments/` — `environment.ts` (local dev: relative URLs), `environment.production.ts` (computes `serverUrl` from `window.location` + `/maia`), plus `demo`/`collaudo`/`complit`/`demo-articolo` variants selected via `fileReplacements` in `angular.json`.

## Backend & proxy

- `angular.json` (`serve.options.proxyConfig`) points to **`src/proxy.conf.json`** — a **gitignored, machine-specific** file. On a fresh clone run once: `cp src/proxy_stub.conf.json src/proxy.conf.json`, then fill it with your backend target (`{}` = no proxy).
- Versioned default in the repo: `src/proxy_stub.conf.json` (empty stub).
- Local instance used in this project targets **`https://klabsrv:19443`** = test VM (Alpine, `10.10.0.19`, in the NAT subnet `10.10.0.0/24` of the KVM host `klabsrv`, port-forwarded). Apache there exposes the backend under **`/maia/maia/…`**, so `pathRewrite`:
  - `/api` → `/maia/maia/api`
  - `/lexo` → `/maia/maia/lexo` (LexO, still used by ontology/lexicon/dictionary services)
  - `/texto` → `/maia/maia/texto` (TexO)
  - `secure:false`, `changeOrigin:true`. Verified 2026-11-04 (401/403 from Spring through `ng serve`). The legacy CASH `/cash` entry was **removed** (app fully replaced by TexO).
- **Deploy scenarios** (same artifact for both): production `https://klab.ilc.cnr.it/maia-vocabo/` (behind the klab reverse proxy, port 443) and test `https://klabsrv:19443/maia/` (KVM NAT). Build with `--base-href=""` (what both serve).
- **Runtime backend URL** (`environment.production.ts`): `origin` (scheme+host+**port**) + UI folder + `/maia` → e.g. `https://klabsrv:19443/maia/maia/api`. The **double `/maia` is the platform convention, not a bug** (also in prod: `/maia-vocabo/maia/api`). Never use `location.hostname` (drops the port). Optional no-rebuild override: `window.__MAIA_CONFIG = {apiBaseUrl, lexoBaseUrl, textoBaseUrl}` in `index.html`.
- **Login flow**: POST `/api/authentication/authenticate` `{username,password}` → JWT as plain text; then `/api/...` calls.

## Gotchas for AI agents

- **quill is still 1.3.7** (moderate XSS advisory). On `master` quill 2 breaks primeng 14's `p-editor` (empty editor). On the upgrade branch PrimeNG 21 works with quill 1.3.7; quill 2 changes the HTML saved by the editors (lists, formats) used by the dictionary and the PDF export: **open decision, test the stored data before switching**.
- **Do NOT bump primeng/@ngx-translate on `master`** without the Angular upgrade.
- **npm overrides** (none left on the upgrade branch: the 43 Angular-14-era ones were removed because they forced old versions): you may NOT override a package that is also a *direct dependency* (`EOVERRIDE`). For multi-major transitive deps use version-keyed keys, e.g. `"minimatch@3": "3.1.4", "minimatch@9": "9.0.8"`. Verify target versions exist before writing them (some advisories are *unfixed* — e.g. newest tar `<=7.5.18` critical had no patch until 7.5.22 was published).
- Always check `node -v` before building: Node 16.20.2 on `master`, Node 22.23.4 on `upgrade/angular-21`.
- Test a deploy package **before** handing it over: `python3 e2e/tools/serve-package.py dist/projectx-fe 8099` (same topology as the test VM) + full e2e with `E2E_BASE_URL=http://127.0.0.1:8099/maia/`.
- `NG0100: ExpressionChangedAfterItHasBeenCheckedError` in dev on the lexicon tile (`workspace-lexicon-edit-tile`, `[scrollHeight]="panelHeight-40+'px'"`, panelHeight set in `ngAfterViewInit`) is **cosmetic and dev-only** — ignore.
- `bootstrap-autofill-overlay.js` console errors come from the Bitwarden browser extension — ignore.
- **Upgrade target is Angular 21 + PrimeNG 21** (last MIT PrimeNG). **PrimeNG 22 and primeicons 8 are proprietary (PrimeUI license, key required)** — do not install them. The future v22 step will evaluate `@openng/optimus-ui` (MIT fork of PrimeNG 21).
- **jsPanel4 is abandoned** (last release 2022) and its layouts are **persisted in maia-be** (`tile.tileConfig`, restored via `jsPanel.layout.restoreId`). Keep it during the upgrade; replacement is a separate backlog project.
- Checking out old commits where `src/proxy.conf.json` was still tracked **silently overwrites/deletes the local ignored file** (happened on the 2026-11-04 merge). Recreate it from `src/proxy_stub.conf.json` / this guide.
- **Node on this machine**: `/usr/local/bin/node` = 24.14.1 is the shell default but is **not** an nvm version (`nvm use 24.14.1` fails); `/usr/bin/node` = 18.19.1. Always select explicitly: `nvm use 16.20.2` (master) / `nvm use 22.23.4` (upgrade branch) / `nvm use 24.14.0` (e2e), and check `node -v` before any `npm` command.
- **Never run `npm install` outside the intended folder**: a failed `cd` once installed Playwright into the app's `package.json`/lockfile with npm 11 (reverted via `git checkout` + `npm ci` on Node 16). Put `npm` on the same line as the `cd` check, not after a heredoc. Note: `nvm` breaks under `set -u`.
- **Stopping `ng serve`**: don't `pkill -f "ng serve ..."` from a command that itself contains that string (it kills its own shell, exit 143). Kill the PID listening on port 4200 (`ss -ltnp`). Start the server and run tests **sequentially**, not in parallel tool calls.
- `environment.ts` on `upgrade/angular-21` has `applicationSubTitle: "VocaBO - DEV UPGRADE"`: **revert to `"develop"` before merging into master**.
- **PrimeNG 16+ AutoComplete** `onSelect`/`onUnselect` emit `{originalEvent, value}`: bind handlers with `$event.value`. When upgrading PrimeNG, **diff the `.emit(` payloads** of every used module between versions: handlers typed `any` hide runtime breakages from the compiler.
- **Theme & CSS layers (upgrade branch)** — read `src/styles/README-layer.md` before touching CSS. PrimeNG 18+ has no theme CSS: `src/app/theme/maia-preset.ts` (Lara + saga-blue values) is injected at runtime in layer `primeng`. Order `@layer base, primeng;` (first rule of `src/styles/vendor.css`): `base` = Bootstrap/jsPanel/icons/PrimeFlex 3/Quill + the app's element rules; app class rules and `.p-*` overrides are **unlayered**. `saga-variables.css` keeps the old `--text-color`/`--surface-*` variables (PrimeFlex 3 and app styles use them). `primeng-compat.css` re-creates PrimeNG 17 classes/behaviours still used by templates (`.p-fluid`, `.p-link`, `.p-error`, panel `iconPos="start"`, `p-scroller` flex, table summary/sort icon, tabs panels, disabled opacity, icon-only button fix for PrimeNG 20).
- **PrimeNG host-as-root**: from 18 (`p-select`) and massively from 20 (`p-autocomplete`, `p-multiselect`, `p-treeselect`, `p-menubar`, `p-panel`, `p-table`, `p-tree`…) the custom element **is** the component root: `styleClass` and `class` end up on the same element, and selectors like `#id .p-menubar` / `p-select > .p-select` no longer match. Put layout classes (`col-6`…) on a wrapper div; don't combine `w-100`/`w-full` styleClass with host layout classes.
- **PrimeNG 17 → 21 renamed inputs**: AutoComplete `field` → `optionLabel`, MultiSelect `defaultLabel` → `placeholder` (without it PrimeNG 21 hides the empty label). Chips of AutoComplete `[multiple]`/MultiSelect `display="chip"` are `<p-chip>` since 18: the saga light-blue look is restored via scoped `--p-chip-*` variables (unlayered) in `primeng-compat.css`.
- **PrimeNG 20+ renamed CSS classes**: splitter panels are `.p-splitterpanel` (was `.p-splitter-panel`): CSS or `getElementsByClassName` using the old name silently match nothing (this lost the min-widths of the Lexicon Editor columns and broke an old PrimeNG 14 workaround in the Text window). Search the code for old class names after a PrimeNG upgrade.
- **Tree tables (Lexicon Editor / Explorer)**: icon columns have fixed `rem` widths with `table-layout: fixed`; the name column takes the rest, the note icon is inside the name cell (`.name-cell`, flex). Don't use percentage widths or a fixed `width` on the name cell (the table spreads the free space over all columns).
- **PrimeNG 17 → 21 behaviour changes already handled**: Tree/TreeSelect `metaKeySelection` default false (set `true` where needed); `TreeNode.index` reserved; Select `autoDisplayFirst` removed (no auto first option); `p-orderList` buttons secondary by default (`[buttonProps]="{}"`); Popover content via `<ng-template #content>`; Tabs panels: content stays instantiated (projection), PrimeNG 19 keeps inactive panels in the DOM (hidden via compat CSS).
- **Reference instances** for visual/behavioural diffs (same backend): Angular 14 worktree `/home/simone/maia-fe-ng14` (commit `49474068`, `ng serve --port 4201`, Node 16) and Angular 18/PrimeNG 17 worktree `/home/simone/maia-fe-ng18` (commit `1323f8a8`, `--port 4202`, Node 22). e2e can target them with `E2E_BASE_URL`. Remove with `git worktree remove <path>` when no longer needed.
- **e2e runs change the saved layout of workspace `e2e-smoke`** when a script leaves the workspace (layout saved on route exit): compare screenshots of the same run order, or re-run the smoke test first.
- **Never install PrimeNG `*-lts` versions** (commercial, e.g. `16.9.17-lts`); caret ranges don't pick them.
- Editing `angular.json`: use targeted text replacement (it has mixed tab indentation); a JSON dump reformats the whole file.
- **Several editors AUTOSAVE (no save button)**: the dictionary entry form (`dictionary-entry-full-editor`: `entryNote.valueChanges` + 500 ms debounce → `POST /lexo/update/dictionaryEntry/notes`, the whole note JSON) and the sense definition/fields (`sense-core-editor`). The test VM holds real data (authors like claudia.palmieri): **never type into those fields from a script or an e2e test** unless writes are blocked: `blockWrites(page, testInfo)` in `e2e/tests/support.ts` fulfils every write (`/lexo/(update|create|delete)/`, `PUT/PATCH/DELETE /api/`) with a fake 200 (it also annotates the blocked requests). Incident 2026-11-05: an e2e test typed in the dictionary entry "abbaiare" and in the definition of its sense; both were restored by hand through the app's own endpoints (only `lastUpdate` could not be restored).
- **Rich text editors**: use `<app-rich-text-editor>` (`src/app/forms/rich-text-editor`, in `SharedModule`, a `ControlValueAccessor` around `p-editor`), not a bare `p-editor` (except read-only previews). Reduced toolbar (bold, italic, underline, align, link, special characters ‹Ω› menu with « » – È ’ …, other formats ‹⋯› menu: sup/sub/strike/lists, clear), Quill `formats` whitelist (colours, fonts, headings, images, code are dropped on paste and when loading), dispatches a bubbling DOM `change` on user edits (used by `(change)="onPendingChanges()"`). Pending decision: auto-convert a typed `'` into `’` (the stored notes use `’` 100%, Word autocorrect; typed in the platform it stays `'`).
- **Session expiry / backend errors**: maia-be checks the JWT itself only on `/api` (403 `JWT expired …`); on `/texto` and `/lexo` it forwards the token to TexO/LexO, which answer 401, and maia-be returns a **generic 500 without message** (`{"status":500,"error":"Internal Server Error"}`; also with a missing/garbage token). The frontend therefore cannot rely on the status alone: `SessionService` (called by `AuthenticationInterceptor`) treats as "session over" a 401, a 403 that talks about the jwt, or a 500 **when the token is locally expired** (`StorageService.isExpired()`: earliest of the 90-min stamp and the JWT `exp`), then clears the storage, shows "Sessione scaduta" and goes to `/login`. The "about to be disconnected" timer is in memory only: `AppComponent` re-arms it at startup (`scheduleExpirationWarning`) and re-checks on `visibilitychange`. Don't swallow HTTP errors with `catchError(() => of([]))` without telling the user (the dictionary preview showed "Nessun risultato" when the contexts request failed). Secondary calls that fall back to a default (labels, initial values, "is described in the dictionary") report it with `CommonService.warnBackendErrorOnce(key, error)` (console + one toast per key every 20 s, i18n `BACKEND_ERROR.<key>`); `app-async-tooltip` shows its own translated error and the callers must not swallow the error before it (`showKwicTooltip` no longer does). **Ontology is disabled** in the frontend: `environment.ontologyDisabled: true` (dev and production; `demoHide` also hides it) removes the workspace menu entry and does not reopen saved ontology windows (set it to `false` to re-enable; that is why `/lexo/ontology/data/info` 500 and the explorer NG0100 are gone). Pending: a global notice for unexpected 5xx (decided to skip for now).
- **Default values of tagset fields in new annotations** (interim, until the backend stores a `default` flag on tagset items): `src/app/helpers/annotation-defaults.helper.ts` (`TAGSET_DEFAULT_VALUES`: tagset name → item name, today "Tipo lessicale" → "Parola monorematica"). `applyDefaultTagsetValues` is called by `text-annotation-editor` (only if the annotation has no id) and `multiple-text-annotation-editor` (create mode only: never in edit/delete mode, where the field is a filter). It fills only empty fields and only if the item exists in the tagset; the field stays editable/clearable (the eraser button really clears). The editors share the tagset-items request with `shareReplay(1)`.
- e2e `blockWrites` lets `/texto/util/*` through (kwic search, ais, annotations are POSTs but read-only); other non-GET `/texto/*`, `/lexo/(update|create|delete)/*` and `PUT/PATCH/DELETE /api/*` are faked.
